# C1: whole-chapter ranges in `parse_range`

Task: extend `bible_core::bible::reference::parse_range` so whole-chapter
ranges such as `Rom 8-9` parse into the existing `VerseRange` type. Base:
`d6bc6b4` (`feat(bible-core): add verse range parsing`). Cross-chapter verse
ranges (`Gen 1:1-2:3`) already work and are out of scope except as
regressions (SHALL 11).

Today a whole-chapter start followed by a dash returns `None`
(`StartEndpoint::WholeChapter` rejects any end part), so `Rom 8-9`,
`Rom 8-8` and `Rom 8-9:5` all fail to parse.

Notation: `B C:V` is `VerseRef { book_index: B, chapter: C, verse: V }`;
`END` is `VerseRange::END_OF_CHAPTER`. A "chapter range `B C1..C2`" means
`VerseRange { start: B C1:1, end: B C2:END }`. Book indices are canon
positions (Genesis 0, Psalms 18, Song of Solomon 21, Obadiah 30, John 42,
Romans 44, 1 Corinthians 45). Chapter counts come from `canon::CANON`.

Tests: `bible-core/tests/c1_public.rs`, one or more tests per SHALL, named
`shallNN_*`. Check command: `cargo test -p bible-core`.

## Requirements

1. **Public shape frozen.** The implementation SHALL keep, unchanged:
   `parse_range(&str, Option<u8>, Option<u16>) -> Option<VerseRange>` at
   `bible_core::bible::reference::parse_range`; `VerseRef` with public fields
   `book_index: u8`, `chapter: u16`, `verse: u8`; `VerseRange` with public
   fields `start: VerseRef`, `end: VerseRef`; both deriving at least
   `Debug, Clone, Copy, PartialEq, Eq, Hash`; `VerseRange::END_OF_CHAPTER ==
   u8::MAX`. No new required parameters, no new fields.

2. **Whole-chapter range.** For a named book and chapters `C1 < C2`, both in
   canon, `"<book> C1-C2"` SHALL return the chapter range `B C1..C2`
   (`Rom 8-9` gives `44 8:1 .. 44 9:END`). This SHALL hold for abbreviated,
   numbered and multi-word book names (`1 Cor 13-14`, `Song of Solomon 1-2`)
   and up to the book's last chapter (`Psa 149-150`, `Gen 1-50`).

3. **Single chapter as a range.** `"<book> C-C"` SHALL return the same value
   as `"<book> C"`, that is `B C:1 .. B C:END` (`Rom 8-8`, `Oba 1-1`).

4. **Reversed rejected.** `"<book> C1-C2"` with `C2 < C1` SHALL return `None`
   (`Rom 9-8`, `Rom 16-1`).

5. **Out-of-canon rejected.** A chapter range SHALL return `None` when either
   chapter is 0 or exceeds the book's chapter count, or does not fit a `u16`
   (`Rom 8-17`, `Rom 17-18`, `Rom 0-2`, `Rom 8-0`, `Oba 1-2`,
   `Rom 8-70000`). It SHALL NOT panic.

6. **Separators.** The en dash (U+2013) SHALL be accepted wherever `-` is,
   with optional whitespace on either side (`Rom 8–9`, `Rom 8 - 9`,
   `Rom 8 – 9` all equal `Rom 8-9`).

7. **Context book, no context chapter.** With `context_book = Some(B)` and
   `context_chapter = None`, a bare `"C1-C2"` SHALL be read as the chapter
   range `B C1..C2`, subject to SHALLs 3, 4 and 5 (`8-9` with Romans in
   context gives `44 8:1 .. 44 9:END`; `9-8` and `8-17` give `None`).
   See DECISION D2.

8. **Context book and chapter: unchanged.** With both `context_book` and
   `context_chapter` set, a bare `"V1-V2"` SHALL remain a verse range in the
   context chapter (`16-18` with John 3 in context gives `42 3:16 .. 42 3:18`;
   `8-9:5` with Romans 3 gives `44 3:8 .. 44 9:5`). With no context at all,
   `"C1-C2"` SHALL still return `None`.

9. **Explicit book wins.** A named book SHALL override any context:
   `Rom 8-9` with context Genesis 3 still gives `44 8:1 .. 44 9:END`.

10. **Chapter to verse.** `"<book> C1-C2:V"` SHALL return
    `B C1:1 .. B C2:V` (`Rom 8-9:5` gives `44 8:1 .. 44 9:5`;
    `Rom 9-9:5` gives `44 9:1 .. 44 9:5`), with `None` when `C2 < C1`,
    `C2` is out of canon, or `V` is 0. The same holds for a bare
    `"C1-C2:V"` under SHALL 7. DECISION D1 below.

11. **Verse forms unchanged.** Every form `parse_range` accepted at base
    SHALL return the same value: in particular a bare number after the dash
    stays a **verse** when the start names a verse (`Rom 8:5-9` gives
    `44 8:5 .. 44 8:9`), and `John 3:16-18`, `Gen 1:1-2:3`, `Rom 8` and
    `Genesis` are unchanged.

12. **Malformed rejected.** Trailing or dangling input SHALL return `None`:
    `Rom 8-`, `Rom 8-9-10`, `Rom 8-9 extra`, `Rom 8-x`, `Rom 8-1 Cor 2`
    (cross-book), `Rom 8-9:`, `Rom 8-:5`.

## Decisions

**DECISION (owner) D1: meaning of `Rom 8-9:5`.**
Recommended and tested: **chapter to verse**, `Rom 8:1 .. Rom 9:5` (SHALL 10).
It is the conventional reading of citations such as `Gen 1–2:3`, and it
composes the two endpoint forms the parser already has. Alternatives:
(a) reject with `None`, today's behaviour, the most conservative;
(b) treat `9:5` as a typo and read only `Rom 8-9` (silently discards input,
not recommended). Picking (a) means deleting `shall10_*` and adding the
inputs to SHALL 12.

**DECISION (owner) D2: bare `C1-C2` with only a context book.**
Recommended and tested: **chapters** (SHALL 7), as the runbook asks. This
reverses one assertion in the base inline suite
(`reference.rs`, `range_needs_context_none`:
`parse_range("16-18", Some(42), None).is_none()`), which asserted the old
"needs a chapter" behaviour. That single assertion was removed in the spec
commit, with a comment pointing here, so the base suite is not
self-contradictory; the rest of that test stays. Alternative: keep `None`
without a context chapter and drop SHALL 7 (then restore the assertion).

## Out of scope

- `parse_reference` and the app/command palette (`parse_range` has no caller
  yet).
- A bare book name followed by a dash (`Rom-9`, `Rom - 9`): unspecified,
  untested.
- A single bare number with only a context book (`8`, context Romans, no
  chapter): unchanged, untested.
- Validating verse numbers against per-chapter verse counts (translation data,
  not canon data).
